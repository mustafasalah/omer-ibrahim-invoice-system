# نظام التصميم للواجهة

## 1. اتجاه التصميم

واجهة رسمية، هادئة وسريعة، تستلهم الثقة والنظافة من قطاع المستلزمات الطبية دون استخدام زخارف طبية مباشرة أو مبالغة في اللون. الأولوية للبيانات، الحالات، والحسابات.

## 2. مبادئ

1. **الفاتورة أولًا:** الإجراء الأبرز دائمًا إنشاء/حفظ/إصدار الفاتورة.
2. **المال لا يلتبس:** الأرقام tabular، العناوين دقيقة، والمدفوع والمسترد منفصلان.
3. **الحالة بالنص والرمز:** لا يعتمد المستخدم على اللون.
4. **كثافة عملية:** جداول واضحة دون فراغات كبيرة.
5. **RTL أصلي:** ترتيب منطقي للعربية، مع LTR للأرقام والمعرفات.
6. **الخطأ قريب من سببه:** لا رسائل عامة فقط.
7. **الأوامر الخطرة هادئة لكن واضحة:** لا أحمر مبالغ، ولا تأكيد غامض.

## 5. الخطوط

### العربية

- Noto Sans Arabic، مضمن محليًا.
- بدائل: Tahoma, Arial, sans-serif.

### الإنجليزية والأرقام

- Inter أو خط نظام حديث مضمن/متاح محليًا.
- `font-variant-numeric: tabular-nums`.

### المقياس

| النمط | الحجم/الارتفاع | الوزن |
|---|---|---:|
| Page title | 24/34 px | 800 |
| Section title | 18/28 px | 750 |
| Card title | 14/22 px | 750 |
| Body | 14/24 px | 400 |
| Compact table | 12–13/20 px | 400 |
| Label | 12/18 px | 650 |
| Helper | 11–12/18 px | 400 |
| Metric | 26–32/38 px | 800 |

لا يقل نص الواجهة الأساسي عن 12px.

## 6. المسافات

نظام 4px:

```text
1=4, 2=8, 3=12, 4=16, 5=20, 6=24,
8=32, 10=40, 12=48, 16=64
```

- حشو بطاقة عادية: 20–24px.
- فجوة حقول: 16px.
- ارتفاع input: 44px.
- ارتفاع زر أساسي: 44–48px.
- صف جدول مريح: 52–60px.
- صف مضغوط: 44–48px.

## 7. الزوايا والظلال

| العنصر | نصف القطر |
|---|---:|
| Input/Button | 10–12px |
| Card/Panel | 16px |
| Modal | 18–20px |
| Badge | 999px |

الظلال خفيفة:

- Card: `0 4px 14px rgba(20,58,55,.04)`.
- Floating/modal: `0 18px 50px rgba(16,43,42,.16)`.
- التركيز لا يستبدل بالظل؛ يستخدم ring واضح.

## 8. شبكة التخطيط

- الشريط الجانبي: 264–272px.
- المحتوى الأقصى: 1600px.
- هامش المحتوى: 24–48px حسب العرض.
- محرر الفاتورة الواسع: محتوى `minmax(0,1fr)` وملخص 320–360px.
- الجداول تستخدم العرض الكامل.
- لا توضع بطاقة داخل بطاقة بلا ضرورة.

## 9. الأزرار

### Primary

- Brand 600، نص أبيض.
- لأهم إجراء واحد في المنطقة.
- مثال: إصدار، تسجيل دفعة، إنشاء فاتورة.

### Secondary

- أبيض وحد brand/line.
- مثال: حفظ مسودة، رجوع.

### Tertiary

- بلا حد، نص brand.
- مثال: عرض الكل.

### Destructive

- أحمر داكن وحد خفيف.
- مثال: إلغاء فاتورة، استعادة نسخة.
- لا تستخدم للأرشفة لأنها قابلة للعكس.

كل زر:

- نص فعلي، والرمز مساعد.
- loading state يحفظ العرض.
- disabled state مع سبب عبر helper/tooltip.

## 10. الحقول

- Label أعلى الحقل.
- النجمة فقط للحقول الإلزامية، مع شرح مرة واحدة.
- placeholder مثال، لا يقوم مقام label.
- helper text قبل الخطأ إن وجد.
- error border + icon + نص.
- الأرقام المالية LTR لكن label عربي.
- حقول Decimal تمنع الحروف وتقبل اللصق المنسق.
- لا يعاد تنسيق القيمة أثناء الكتابة بما يحرك المؤشر؛ التنسيق عند blur.

## 11. Autocomplete

- يبدأ بعد حرفين.
- ارتفاع نتيجة 52–60px.
- يبرز الجزء المطابق.
- يعرض بيانات ثانوية محدودة.
- زر حذف منفصل بعنوان وصول واضح.
- keyboard: Up/Down, Enter, Escape.
- نتيجة «استخدام النص كاسم جديد».
- loading وempty state.

## 12. الجداول

- رأس sticky عند القوائم الطويلة.
- محاذاة النص العربي يمينًا.
- الأرقام لجهة النهاية بصريًا وبـLTR.
- hover خفيف.
- صف محدد بخلفية وحد.
- الأعمدة المهمة لا تختفي؛ الأقل أهمية تنتقل لتفاصيل الصف على العرض الصغير.
- قائمة `…` لها accessible name يتضمن رقم الفاتورة.
- pagination واضحة ولا تستخدم infinite scroll للأرشيف.

## 13. الشارات

- ارتفاع 24–28px.
- نقطة/رمز + نص.
- لا تستخدم uppercase الإنجليزية في العربية.
- يمكن جمع شارتين أو ثلاث في الرأس فقط مع مسافات.

## 14. النوافذ

- عرض الدفع/الاسترداد: 520–600px.
- خيارات الطباعة: 620–700px.
- الاستعادة: حتى 720px.
- focus trap.
- Esc يغلق فقط إن لم توجد مدخلات غير محفوظة.
- الإجراء الأساسي في طرف القراءة النهائي المناسب لـRTL.
- التأكيد الخطر يذكر الكائن والأثر.

## 15. الإشعارات

- Toast للنجاح غير الحساس لمدة 4–6 ثوانٍ.
- الأخطاء المرتبطة بحقول تبقى داخل النموذج.
- Banner للأخطاء العامة أو الخادم غير المتصل.
- لا تستخدم toast وحده لتأكيد حركة مالية؛ تحدث الشاشة وتظهر الحركة.

## 16. الرموز

- مجموعة outline واحدة بسمك موحد.
- الحجم 18–20px في الأزرار، 16px في الجداول.
- `aria-hidden` إذا كان النص يشرحها.
- لا تستخدم رموزًا زخرفية بدل معنى واضح.

## 17. RTL وBiDi

- `<html lang="ar" dir="rtl">`.
- أرقام الفواتير والبريد والهاتف والمبالغ: wrapper بـ`dir="ltr"` و`unicode-bidi:isolate`.
- زر العودة يستخدم سهمًا متوافقًا مع الاتجاه.
- السحب والترتيب يفسر أعلى/أسفل لا يمين/يسار.
- ترتيب الأعمدة يراجع وظيفيًا، لا يعكس آليًا فقط.
- أي واجهة إنجليزية مستقبلية تستخدم tokens نفسها مع `dir=ltr`.

## 18. الحركة

- 120–180ms للتغيرات الصغيرة.
- 180–240ms لفتح modal/drawer.
- لا تستخدم حركة في أرقام مالية قد توحي بتأخير الحساب.
- احترام `prefers-reduced-motion`.
- لا تستخدم parallax أو مؤثرات تسويقية.

## 19. الحالات الفارغة

صياغة عملية:

- لا فواتير: «لم تُنشأ أي فاتورة بعد» + زر إنشاء.
- لا نتائج: «لا توجد نتائج بهذه الفلاتر» + مسح الفلاتر.
- لا دفعات: «لم تسجل دفعات لهذه الفاتورة».
- لا شعارات وكلاء: «يمكن إضافة حتى خمسة شعارات».

لا تستخدم رسومات كبيرة تستهلك مساحة شاشة العمل.

## 20. نبرة النص

- عربية واضحة وقصيرة.
- «إصدار الفاتورة» لا «إرسال».
- «إلغاء الفاتورة» لا «حذف».
- «أرشفة» لا «حذف».
- «استرداد» للأموال، و«استعادة من الأرشيف» للأرشفة.
- تعرض الأفعال بصيغة مباشرة ونتائجها بصيغة ماضية.

## 21. إتاحة الوصول

- WCAG 2.2 AA هدف.
- focus ring: 3px بلون brand مع offset.
- ترتيب Tab يطابق الترتيب المرئي.
- skip link للمحتوى.
- رؤوس جداول فعلية.
- `aria-live` لحالة الحفظ والحساب.
- الرسوم لها جدول أو ملخص.
- مساحة النقر 44px للأوامر الأساسية.
- اختبار تكبير 200%.

## 22. حدود النموذج البصري

النموذج التفاعلي يوضح:

- البنية والتنقل.
- كثافة البيانات.
- الألوان والطباعة.
- حالات الدفع.
- سيناريو إنشاء ومراجعة.

لا يمثل:

- قاعدة بيانات حقيقية.
- صلاحيات فعلية.
- حسابات إنتاج.
- PDF حقيقي.
- نسخًا احتياطية.
