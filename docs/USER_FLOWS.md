# تدفقات المستخدم

## 1. مبادئ التدفق

- يبقى المسار الأساسي لإنشاء الفاتورة في صفحة واحدة قدر الإمكان.
- لا يُنشأ رقم فاتورة قبل أول حفظ ناجح.
- الأوامر الحساسة لا تعتمد على تأكيد عام فقط؛ تعرض الأثر المالي المحدد.
- كل نجاح يعرض نتيجة واضحة ورابطًا للخطوة التالية.
- كل خطأ تحقق يظهر قرب الحقل وضمن ملخص أعلى الصفحة عند الإصدار.
- عند وجود تغييرات غير محفوظة، يحذر النظام قبل المغادرة.

## 2. تسجيل الدخول

**الفاعل:** مدير أو موظف.

1. يفتح المستخدم عنوان النظام المحلي.
2. إذا لا توجد جلسة، ينتقل إلى `/login`.
3. يدخل اسم المستخدم وكلمة المرور.
4. يرسل النظام البيانات عبر طلب محمي.
5. يتحقق من الحساب والحالة وكلمة المرور وحد المحاولات.
6. عند النجاح ينشئ جلسة وينقله إلى لوحة التحكم.
7. إذا كانت كلمة المرور مؤقتة، ينتقل إلى شاشة تغييرها قبل بقية النظام.

**الحالات البديلة:**

- بيانات خاطئة: رسالة عامة دون تحديد أي الحقلين.
- مستخدم معطل: رسالة «تعذر تسجيل الدخول؛ راجع مدير النظام».
- محاولات كثيرة: انتظار تدريجي ورسالة زمن المحاولة التالية.
- انقطاع الخادم: رسالة «تعذر الاتصال بالجهاز المضيف» مع إعادة المحاولة.

## 3. إنشاء فاتورة جديدة

**الفاعل:** مدير أو موظف.

1. يضغط «إنشاء فاتورة».
2. تفتح `/invoices/new` بدون رقم محجوز.
3. يعرض النظام تاريخ اليوم، العملة، والضريبة والشروط الافتراضية.
4. يكتب المستفيد أو يختاره من الاقتراحات.
5. يضيف بندًا أو أكثر ويختار منتجات سابقة أو يكتب منتجًا جديدًا.
6. يدخل الكمية والسعر والخصم والضريبة.
7. يرى الإجماليات تتحدث فورًا كمعاينة.
8. يمكنه إضافة ملاحظات وشروط دفع وتاريخ استحقاق.
9. يختار:
   - «حفظ كمسودة».
   - «إصدار الفاتورة».

### 3.1 حفظ المسودة

1. يعيد الخادم الحساب.
2. يحجز رقمًا ذريًا إذا كانت أول مرة.
3. يحفظ المستفيد والمنتجات الجديدة كاقتراحات.
4. يحفظ الفاتورة والبنود والسجل في transaction.
5. يعرض إشعارًا: «حُفظت المسودة OI-...».
6. يبقى المستخدم في المحرر أو يفتح التفاصيل حسب اختياره.

### 3.2 إصدار الفاتورة

1. يتحقق الخادم من الحقول الكاملة.
2. عند وجود خطأ، لا يغير الحالة ويعيد قائمة حقول.
3. عند النجاح يلتقط بيانات الطباعة الحالية.
4. يغير الحالة إلى «صادرة» ويسجل المستخدم والوقت.
5. يفتح شاشة التفاصيل مع أزرار المعاينة والطباعة وتسجيل دفعة.

## 4. استخدام اقتراح مستفيد

1. يكتب المستخدم حرفين أو أكثر.
2. بعد مهلة قصيرة تظهر نتائج مطابقة بالاسم والهاتف.
3. يتنقل بالأسهم ويختار بـ Enter أو النقر.
4. تُملأ البيانات الاختيارية.
5. يمكن تعديل نسخة الفاتورة دون تغيير الاقتراح فورًا.
6. عند الحفظ، إذا تغيرت البيانات، يسأل النظام بصورة غير معطلة: «تحديث البيانات المقترحة مستقبلًا؟» والافتراضي نعم للحقول غير الفارغة.

### حذف اقتراح

1. يضغط زر الحذف بجانب النتيجة.
2. يعرض تأكيدًا صغيرًا: «لن تتأثر الفواتير السابقة».
3. بعد التأكيد يختفي من النتائج.
4. يبقى النص الحالي في الفاتورة كما هو.

## 5. استخدام اقتراح منتج

1. يكتب اسم المنتج داخل البند.
2. تظهر اقتراحات بالاسم والوحدة والسعر الأخير.
3. عند الاختيار تُملأ حقول اللقطة.
4. يغير المستخدم السعر أو الوصف لهذا البند إذا أراد.
5. عند حفظ الفاتورة، يصبح آخر سعر ناجح هو السعر المقترح مستقبلًا.
6. حذف الاقتراح لا يحذف البند أو أي تاريخ.

## 6. إضافة وإدارة البنود

- زر «إضافة بند» يضيف صفًا بعد آخر صف.
- الضغط على Enter في آخر حقل للصف يضيف صفًا جديدًا.
- يمكن سحب مقبض الترتيب أو استخدام «تحريك لأعلى/أسفل».
- حذف صف يحتاج تأكيدًا فقط إذا احتوى بيانات.
- إذا كان الصف الوحيد، يمسح محتواه بدل إزالته من الشاشة.
- تعرض الأخطاء في الصف نفسه.
- على الشاشات الضيقة يتحول كل صف إلى بطاقة حقول مرتبة.

## 7. تعديل مسودة

1. يفتح المستخدم المسودة.
2. يضغط «تعديل».
3. يحمل النظام أحدث `row_version`.
4. يجري التغييرات ويحفظ.
5. إذا عدّل مستخدم آخر السجل، يرفض الحفظ ويعرض:
   - «تحميل النسخة الأحدث».
   - «نسخ مدخلاتي» لمنع الفقد.
6. لا يوجد دمج تلقائي لبنود مالية.

## 8. تعديل فاتورة صادرة

**الفاعل:** مدير.

1. يفتح التفاصيل ويضغط «تعديل الفاتورة الصادرة».
2. يعرض النظام تحذيرًا وحركاتها المالية.
3. يدخل سبب التعديل.
4. يغير البيانات.
5. يعيد الخادم الحساب ويطبق حد صافي المحصل.
6. إذا أصبح الإجمالي أقل من الصافي، يمنع الحفظ ويعرض الفرق الواجب استرداده.
7. عند النجاح يسجل القيم قبل/بعد ويعيد اشتقاق حالة الدفع.
8. يعرض شريطًا في التفاصيل بأن الفاتورة عُدلت بعد الإصدار.

## 9. تفاصيل الفاتورة

1. تفتح من البحث أو لوحة التحكم.
2. يعرض الرأس رقم الفاتورة وحالاتها الثلاث.
3. تعرض بطاقات الإجمالي، المدفوع، المسترد، الصافي، والمتبقي.
4. تعرض تبويبات:
   - البيانات والبنود.
   - الدفعات والاستردادات.
   - سجل الفاتورة.
5. تظهر الأوامر وفق الحالة والصلاحية.

## 10. تسجيل دفعة

**شرط البداية:** فاتورة صادرة، غير مؤرشفة، ولها متبقٍ أكبر من صفر.

1. يضغط المستخدم «تسجيل دفعة».
2. تفتح نافذة تعرض الإجمالي والمدفوع والمتبقي.
3. يكون مبلغ الدفعة افتراضيًا مساويًا للمتبقي.
4. يحدد التاريخ والطريقة والمرجع والملاحظة.
5. عند «أخرى» يدخل وصف الطريقة.
6. يضغط «تسجيل الدفعة».
7. يتحقق الخادم من الحد ويضيف الحركة والسجل ويعيد الحالة ذريًا.
8. تعرض النتيجة والحالة الجديدة.

**خطأ تزامن:** إذا سجل مستخدم آخر دفعة، يعيد النظام أحدث المتبقي ويطلب تعديل المبلغ.

## 11. تسجيل استرداد

**الفاعل:** مدير.

1. يضغط «تسجيل استرداد».
2. تعرض النافذة المدفوع والمسترد والقابل للاسترداد.
3. يحدد المبلغ والتاريخ وطريقة الرد والسبب الإلزامي.
4. يمكنه ربطه بدفعة محددة.
5. تعرض معاينة صافي المحصل والمتبقي والحالة الناتجة.
6. يعيد إدخال كلمة المرور فقط إذا كان الإجراء جزءًا من تجاوز إلغاء غير مسوّى، وليس لكل استرداد عادي.
7. يؤكد.
8. يسجل النظام الحركة ويعيد الحالة.

## 12. إبطال حركة

1. يفتح المدير قائمة الحركة.
2. يختار «إبطال».
3. يعرض الأثر على صافي المحصل والحالة.
4. يدخل السبب ويؤكد.
5. يمنع الإبطال إذا خالف تسلسل الاستردادات.
6. تبقى الحركة ظاهرة بحالة «مبطلة» ويتوسطها خط بصري.

## 13. أرشفة وإلغاء أرشفة

1. يختار المستخدم فاتورة واحدة من التفاصيل أو عدة فواتير من الأرشيف.
2. يضغط «أرشفة».
3. يؤكد العدد، دون تغيير الحالات.
4. تختفي من العرض الافتراضي وتبقى في التقارير.
5. عند عرض المؤرشف، يختار «استعادة من الأرشيف».
6. تعود إلى العرض النشط بنفس الحالة والدفع.

## 14. البحث في الأرشيف

1. يفتح `/invoices`.
2. يكتب نصًا موحدًا للرقم أو المستفيد أو المنتج.
3. يعرض النظام النتائج بعد مهلة قصيرة أو Enter.
4. يضيف فلاتر الحالة والدفع والتاريخ والمبلغ والمنشئ.
5. يختار عرض المؤرشف: إخفاء، إظهار فقط، أو الجميع.
6. يرتب النتائج.
7. يفتح فاتورة أو ينفذ أمرًا من قائمة الصف.
8. يمكن مسح كل الفلاتر بنقرة واحدة.

**الحالة الفارغة:** توضح الفلاتر النشطة وتقترح مسحها، ولا تقول إن النظام بلا فواتير ما لم تكن القاعدة فارغة فعلًا.

## 15. نسخ فاتورة

1. يختار «نسخ إلى فاتورة جديدة».
2. تعرض نافذة ما سيُنسخ وما لن يُنسخ.
3. يختار الاحتفاظ بإعدادات الضريبة الأصلية أو الحالية.
4. ينشئ النظام مسودة جديدة برقم جديد.
5. ينتقل إلى المحرر لمراجعتها.

## 16. المعاينة والطباعة وPDF

1. يضغط «معاينة وطباعة».
2. تفتح معاينة A4 مع أدوات خارج الورقة.
3. يضغط «طباعة» أو «تنزيل PDF».
4. تفتح نافذة الخيارات:
   - تضمين الختم والتوقيع.
   - بدون الختم والتوقيع.
   - ألوان أو أبيض وأسود.
5. يحفظ النظام الخيار للجلسة فقط.
6. للطباعة: يستدعي نافذة المتصفح بعد تحميل الأصول.
7. لـ PDF: يولد الخادم الملف من نفس القالب وينزله بالاسم المطلوب.
8. لا يتغير أي أصل محفوظ في الإعدادات.

## 17. التقارير

1. يفتح المستخدم شاشة التقارير.
2. الفترة الافتراضية هي الشهر الحالي.
3. يغير التاريخ أو يختار فترة سريعة.
4. تتحدث كل البطاقات والجداول بالمجال نفسه.
5. يفتح بطاقة أو نقطة رسم للانتقال إلى فواتير مفلترة.
6. يطبع التقرير أو ينزله PDF.

## 18. تعديل الإعدادات

**الفاعل:** مدير.

1. يفتح التبويب المناسب.
2. يعدل البيانات ويرى معاينة فاتورة مصغرة.
3. عند رفع صورة يتحقق النظام من النوع والحجم والأبعاد.
4. لا تُحفظ التغييرات حتى ضغط «حفظ».
5. يعرض النظام أن التغييرات تطبق على الفواتير الجديدة.
6. تغيير الترقيم يعرض الرقم التالي المتوقع وتحذيرًا.

## 19. إدارة شعارات الوكلاء

1. يرفع المدير صورة أو يسحبها لمنطقة الرفع.
2. يمنع الشعار السادس.
3. تعرض بطاقة كل شعار بمعاينة واسم وبدائل استبدال/حذف.
4. يسحب البطاقات لإعادة الترتيب.
5. تحفظ العملية دفعة واحدة.
6. تظهر معاينة التذييل بنسبة احتواء صحيحة.

## 20. إدارة المستخدمين

1. يفتح المدير شاشة المستخدمين.
2. ينشئ مستخدمًا باسم ظاهر واسم دخول ودور.
3. يولد أو يدخل كلمة مؤقتة.
4. ينسخها مرة واحدة خارج النظام بطريقة آمنة.
5. يمكنه تعطيل/تفعيل أو إعادة تعيين كلمة مرور.
6. يمنع تعطيل آخر مدير.

## 21. إنشاء نسخة احتياطية

1. يفتح المدير تبويب النسخ الاحتياطي.
2. يضغط «إنشاء وتنزيل نسخة».
3. يعرض النظام تقدمًا قصيرًا ويمنع كتابة متعارضة للحظة snapshot.
4. ينشئ ملفًا كاملًا باسم مؤرخ.
5. يتحقق من checksum.
6. يبدأ التنزيل.
7. يسجل العملية دون تسجيل مسار جهاز المستخدم.

## 22. استعادة نسخة

1. يضغط المدير «استعادة».
2. يقرأ تحذيرًا بأن البيانات الحالية ستستبدل.
3. يختار ملف النسخة.
4. يتحقق النظام من الامتداد والبيان وchecksum والإصدار والسلامة في مساحة مؤقتة.
5. يعرض ملخص النسخة: التاريخ، عدد الفواتير، عدد الوسائط، إصدار schema.
6. يعيد المدير إدخال كلمة المرور ويكتب كلمة تأكيد `استعادة`.
7. يدخل النظام وضع صيانة قصيرًا.
8. ينشئ نسخة أمان تلقائية من الوضع الحالي.
9. يبدل البيانات ذريًا ويعيد فتح القاعدة.
10. عند النجاح ينهي كل الجلسات ويطلب الدخول.
11. عند الفشل يرجع للوضع السابق ويعرض سببًا آمنًا.

## 23. مراجعة سجل العمليات

1. يفتح المدير الشاشة.
2. يفلتر بالمستخدم والنوع والفاتورة والتاريخ.
3. يفتح سجلًا لرؤية وصف التغيير.
4. القيم الحساسة تحجب.
5. لا توجد أزرار تعديل أو حذف.
